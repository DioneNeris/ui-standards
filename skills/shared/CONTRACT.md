# Shared V1 instructions

Read `framework/contracts/G2-CONTRATO-V1-CANDIDATO.md` and validate the baseline using `python3 <package-root>/scripts/validate.py baseline --package-root <package-root>` before a normative evaluation. Treat the package source provenance as unverified and identify the pinned commit. A validation error blocks normative conclusions and dependent changes. Follow GOV-002–004: report conflict; do not invent an exception; proven violations take precedence over missing methods; conforming results require sufficient evidence for all applicable methods. Use complete evidence and validate request/result JSON as specified by the contract. Do not claim WCAG conformity. Report only actions actually performed and limitations. Reject unauthorized output or changes. For file output require explicit authorization. When no enforceable read-only boundary is available, stop rather than assert enforcement.

The baseline commit identifies the historical normative source; a newer HEAD is expected and is not a conflict by itself. Validate normative file integrity against the pinned source commit, not HEAD equality. For no-write validation, pipe a pre-existing JSON payload to `python3 <package-root>/scripts/validate.py request --package-root <package-root> --file -`, or a result payload with `--file - --request <authorized-request-file>`. A command denial is an environment limitation: use only a preapproved equivalent invocation (one command per call, with documented absolute paths), otherwise stop and report BLOQUEADA. Never broaden the allowlist or assume that text restrictions constitute enforced read-only isolation.
